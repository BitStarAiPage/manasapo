# まなサポ｜デザイン・実装仕様

## デザインの基準

`references/approved-design.png` が採用された構成・トーンの基準です。画面全体を1枚の画像としてWebページに貼る実装は不可。見出し、本文、写真、図形、ボタンを、それぞれHTML/CSSで組んでください。

画像は縦長の構成見本です。圧縮された本文・省略されたテキスト・架空の写真・簡略化されたフォームは最終仕様ではありません。本文は `CONTENT.md` の全文を使い、その分だけ高さを確保します。

### 参考サイトと取り入れる部分

- https://deepground.jp/ ：大きな文字、人物と文字の重なり、背景色の大胆な切り替え、塾の熱量が伝わる構成。これは今回最も重視する視覚的な参考です。
- https://top-prep.co.jp/ ：大きな実写写真、写真と文章を交互に見せる構成、教室のリアルな空気感。
- 現サイト：https://sites.google.com/view/manasapo/%E3%83%9B%E3%83%BC%E3%83%A0?authuser=0&pli=1

外部サイトの閲覧ができなくても、同梱の採用画像と仕様書で実装を進められます。先行する淡色・カード中心の案は採用していません。参考サイトからロゴ・人物イラスト・写真・キャッチコピーを流用しないでください。

## 見た目

| 要素 | 指定 |
| --- | --- |
| メイン | サンフラワーイエロー `#FFD84D`。FV、講師紹介、最後のCTAで広い面として使う |
| ベース | アイボリー `#FFFDF5` と白。本文セクションの余白 |
| 文字・黒背景 | チャコール `#202020` |
| サブ | 淡いミント `#DFF1E7`。コース紹介など |
| 本文 | PC/SPとも基本16px以上、行間1.8〜2程度。読みやすさに応じて調整 |
| 見出し | 日本語ゴシックの太いウェイト。FVは特に大きく、PCで80〜120px程度を起点に調整 |
| ロゴ | 黒い支給画像を使い、縦横比を保つ。白背景が気になる場合は白い余白面に置くなど、元画像を壊さず馴染ませる |
| あしらい | 手書き風の矢印、丸、下線。余白に限定し、顔や文字を隠さない |
| 写真 | 自然な明るさ、角丸や一部切り抜きで動きを出す。受領した写真の構図に合わせて調整 |
| 動き | 短いフェード・小さな移動のみ。reduced-motionに対応し、動きがなくても全情報が見える |

全幅の背景色と、本文の読みやすい最大幅を分ける。目安として本文コンテナは1120〜1280px、PCの左右余白は48〜64px、SPは20〜24px。写真や大きな装飾はコンテナから一部はみ出してもよいが、横スクロールは発生させない。

黄色背景上の本文とボタン文字は黒。黒背景には白・黄色を使う。黄色の文字を白背景の本文に使わない。本文のコントラストを確保する。

### FV

- キャッチコピーは正確に `「教わる」から、「自分で学べる」へ。` とする。改行で整える。
- 写真、切り抜き人物、文字が層になる構成。ただしキャッチコピーは最後まで読め、人物の顔を文字で隠さない。
- 切り抜き素材がまだなければ、後でPNG/WebPを入れられるレイヤー枠を先に作る。無理に背景を除去したり、輪郭をAIで作り直したりしない。
- ヘッダーはロゴと主要ページ内リンク。「無料体験に申し込む」を強調。「お問い合わせ」も配置。
- 同じフォームへ2つのCTAが移動する場合、体験希望日は任意なので問い合わせだけでも進める設計にする。

### コースと長文の扱い

- 学年別入口はページ内リンクとし、両コースを同じページ内に残す。
- コースの導入文・ポイント・受講時間は通常表示。
- 5つの受講例は、それぞれ独立した `details/summary` 等で展開可能にする。閉じた状態でもタイトル・学年・受講内容を分かるようにする。
- 同時に複数の事例を開ける構造でよい。閉じた本文も実際のDOMに保持し、全文が読めるようにする。
- スクリーンショットに入りきらないからといって、本文を切る・省く・書き換える処理はしない。
- 生徒の変化のCASE 01は、サイトの核なので原則として本文を開いた状態で読ませる。

## 写真の差し替え

画像パス、代替テキスト、切り抜き位置を1か所のデータファイルで変更できるようにする。たとえば `src/content/media.ts` を用意し、実際のフォルダ構成に合わせて調整する。画像未指定時は同じ縦横比のプレースホルダーを表示し、レイアウトが崩れないようにする。

開発プレビューのプレースホルダーには「講師と生徒が話す写真」など、入れる内容が分かる名前を表示してよい。これは制作時だけの表示とし、完成サイトで架空の写真や実績を装わない。生成画像のサンプル写真を切り出して実写真として使わない。

| キー案 | 写真の内容 | 比率・備考 |
| --- | --- | --- |
| `heroMain` | 生徒と講師が対話している様子 | 4:3〜3:2。FVの主役 |
| `heroCutout` | 対話する講師・生徒の切り抜き | 透過画像を後から置ける層。なくても破綻しない |
| `heroWhiteboard` | 生徒がホワイトボードに書く様子 | 4:3。小さな重ね写真 |
| `updates[]` | 最近の教室、学習、活動 | 3:2〜4:3。各投稿の実タイトル・日付・URLも後日 |
| `philosophy` | 自分で考える、整理する生徒 | 4:3 |
| `courseJunior` | 小・中学生への指導 | 3:2 |
| `courseSenior` | 高校生の学習 | 3:2 |
| `features[1..4]` | 個別指導、勉強法の相談、連携、教室外活動 | 4:3を基本に配置 |
| `staff[]` | 講師・スタッフの顔写真 | 1:1〜4:5。人数はデータに合わせる |
| `case01` | 実際の「呪い」勉強法のホワイトボード | 3:2。内容が見える大きさを確保 |
| `message` | 瀬尾さん、または実際の教室 | 4:3。対応する実写真を支給後に設定 |
| `classroom` | 教室の内観・入口 | 4:3。来塾時の目印にもなる |

画像は縦横比を保持し、必要なときだけ `object-fit: cover` と `object-position` でトリミング。顔やホワイトボードの重要部分を切らない。FV以外は遅延読み込みを検討し、画像の幅・高さを指定する。

## フォーム

必須項目は保護者名、子ども名、電話番号、メール、学年の5つ。体験希望日と質問は任意。電話は数値型ではなく `type="tel"`、メールは `type="email"` とする。プレースホルダーだけで項目名を表さず、常にlabelを表示する。

学年は小1〜小6、中1〜中3、高1〜高3の選択肢を用意する。範囲外の対象を勝手に追加しない。学校名・住所・成績などの追加項目を求めない。

「体験授業希望日」は希望の受付であり、予約確定ではない。空き枠を取得していないのに、空き状況や予約確定を表示しない。

バックエンド未接続時は送信ボタンを無効にするか、クリック時に「送信機能は準備中です」と正しく伝える開発状態にする。架空の成功トースト・送信完了ページ・APIキーは作らない。入力値をコンソールに出したりブラウザに永続保存したりしない。原稿のメールアドレスには直接連絡用リンクを設定できる。

## スマートフォン

- 390px前後を基準に、375pxでも横スクロールしないよう確認する。
- FVはキャッチコピー→写真→説明→CTAの流れを基準に、最初の画面でも写真が見える高さを意識する。
- PCの巨大見出し・はみ出しをそのまま縮小せず、SP用に改行・重なり位置・余白を作る。
- コースと特徴は1列。プロフィールはタップしやすい2列または1列。横スライド前提にしない。
- 画面下の無料体験CTAを固定する場合、本文末尾の余白とセーフエリアを確保し、フォーム表示中は隠す。
- リンク・ボタンは十分なタップ領域。アコーディオン、メニュー、フォームはキーボード操作・フォーカス表示にも対応。

## 確認すべき点

- 1440px前後のPCと390px前後のSPで、写真の重なり・文字の読みやすさ・背景切り替えを確認する。
- 本文が長い箇所のはみ出し、固定CTAによる隠れ、メニュー開閉、ページ内リンクの見出し位置を確認する。
- 受講例の展開と全フォームの入力エラーを確認する。実メール送信は接続後に別途確認。
- 画像が未指定でも、レイアウトの比率と高さが保たれるか確認する。
- 実行できた検証と未検証を区別して報告する。

## 原稿に関する確認メモ（本文へ自動反映しない）

先方チェック済みなので、以下は勝手に直さず、原文を保持したうえで制作報告に記載する。

- 「オンラン授業」
- 「I日1時間程度」
- 「週1回 数」：科目・受講時間が記載途中の可能性
- 「生かすことかできない」
- 「ご家庭がワンチームでとなり」
- 「成績を納めていた」

料金、講師プロフィール、最新投稿、実写真、フォーム送信先、公開先は、この資料では確定していない。埋まっていない項目は、勝手に事実を作らず差し替え可能な構造にする。料金など指定構成にない項目を独断で追加しない。
